## 1. 当前阶段结论

当前最关键结论：

```text
Web-Bird 上严格筛选/约 50% Otsu 更有效，both only 在 LoRA 3-seed 下最强。
Web-Aircraft 和 Web-Car 上原始 Otsu 约 50% 过度过滤，0.9 固定保留比例明显更合理。
跨三子集看，both only 不是稳定主方法；centroid 0.9 是目前更稳的跨子集 filtering baseline。
GCS 初步解释了这种差异：Bird 的类原型紧凑度明显低于 Aircraft/Car。
```

最新三子集现象：

```text
Bird: orig/Otsu 下 both only 与 centroid 最强。
Aircraft: 0.9 下 centroid、GCDD+Proto、all noisy 很接近，centroid 略高。
Car: 0.9 下 centroid 明确最强，并超过 all noisy。
```

因此当前不应写成 “agreement clean selection 跨数据集稳定最优”。更稳妥的主线是：不同 FGVC 子集需要不同 clean retention 强度；低比例 agreement 在 Bird 有效，高保留 centroid/prototype anchor 在 Aircraft/Car 更稳。

## 8. GCS 数据集紧凑度分析

输出目录：

```text
outputs/gcs_analysis/
```

计算定义：

```text
GCS_sample_mean = mean_i s_i_proto
GCS_class_balanced = mean_c mean_{i:y_i=c} s_i_proto
s_i_proto = z_i^T m_{y_i}
```

其中 `GCS_class_balanced` 作为主指标，因为它对每个类别等权，避免大类主导数据集均值。

验证表：

| dataset | samples | classes | GCS_sample_mean | GCS_class_balanced | best strict | best high-ratio |
| --- | ---: | ---: | ---: | ---: | --- | --- |
| Web-Bird | 18386 | 200 | 0.497459 | 0.496987 | yes | no |
| Web-Car | 21448 | 196 | 0.558499 | 0.558654 | no | yes |
| Web-Aircraft | 13498 | 100 | 0.639561 | 0.640106 | no | yes |

结论：

```text
GCS_class_balanced 排序为 Bird < Car < Aircraft。
虽然不是 Bird < Aircraft < Car，但关键现象成立：Bird 明显低于 Aircraft/Car。
低 GCS 的 Bird 更适合 strict mode，即 both only / agreement filtering。
高 GCS 的 Aircraft/Car 更适合 relaxed mode，即 centroid top-0.9。
```

当前三子集可用的简单路由阈值：

```text
if GCS_class_balanced < 0.527820:
    strict mode
else:
    relaxed mode
```

注意：该阈值目前只是基于三个子集的经验分割点，需要更多数据集验证后才能作为稳定规则写入方法部分。

## 10. 当前方法判断

当前最稳判断：

```text
1. 原始 Full GCDD-clean 整体较弱。
2. Web-Bird 上 both only 有优势，但该结论不能迁移到 Aircraft/Car。
3. Aircraft/Car 上原始 Otsu 约 50% 过度过滤，0.9 固定保留比例明显更稳。

  CUB 最优当前是 p=0.4；
  Web-Car 最优当前是 p=0.8，p=0.6 已经过筛。

因此 PGDF 的下一步不是固定某个 p，而是设计 adaptive proto gate 或至少按数据集选择 gate 强度。
Auto p 已初步验证 adaptive p 的方向，但 Web-Aircraft 显示不是所有数据集都适合 PGDF；后续需要补 method-level routing。
Web-Car auto2 低于手动 p=0.8，仍需要补多 seed 并检查 auto 调度是否与手动 p=0.8 完全可比。
建议 CUB 可选补 p=0.3 判断是否继续上升或开始过筛；Web-Car 暂停继续扫低 p，p=0.8 可作为当前最佳候选。
```

### 15.3 当前判断

```text
FINE-DINOv2 feature 是当前最强外部 baseline，但数据集依赖明显：
  CUB 上达到 77.93，明显超过 Dynamic；
  FGVC-Aircraft 上达到 60.22，略高于 Dynamic；
  Stanford Cars 上只有 58.21，明显低于 Dynamic。

JoCoR 在 Stanford Cars 上是最强外部 baseline，达到 62.32，但仍低于 Dynamic 62.99。
Co-teaching / JoCoR 在 FGVC-Aircraft 上只略高于 Dynamic，在 CUB 上均低于 Dynamic。

PGDF auto 在三个数据集上均超过最强外部 baseline：
  CUB +2.15 pp；
  Stanford Cars +9.25 pp；
  FGVC-Aircraft +4.92 pp。

FINE Cars 的 purity=71.43%，但 Top-1 只有 58.21，说明 purity 高不必然带来更高准确率；样本代表性、类别覆盖和筛选视角同样重要。
```

一个实现口径细节：

```text
Co-teaching / JoCoR 命令名义 remember_rate=0.8。
但 batch_size=16 时，class-free mini-batch small-loss 使用 floor(16 * 0.8)=12，
因此实际 selected_ratio 约为 12/16=75.01%。
这不是训练错误，但论文表中应避免把 selected ratio 写成精确 80%。
```
